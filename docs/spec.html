SKILL.md Specification

The SKILL.md Format

A SKILL.md file defines a reusable skill that can be installed into any AI agent using pour. This spec defines the format so anyone can write and share skills that work consistently across the community.

File Location

A SKILL.md can live in the root of a repo (single skill) or inside named subfolders (multiple skills).

# single skill repo
my-repo/
└── SKILL.md

# multi-skill repo
my-repo/
├── code-reviewer/
│   └── SKILL.md
└── email-drafter/
    └── SKILL.md

pour automatically scans all top-level directories — the folder name doesn't matter, it just needs a SKILL.md inside it.

Format

A SKILL.md is a Markdown file with optional YAML frontmatter followed by the skill instructions.

---
name: code-reviewer
description: Reviews code for bugs, readability, and best practices
version: 1.0.0
tags:
  - coding
  - review
agents:
  - claude
  - cursor
---

# Code Reviewer

You are an expert code reviewer. When asked to review code,
focus on correctness, readability, and performance...

Frontmatter Fields

FieldRequiredTypeDescription
name required string Unique identifier. Lowercase, hyphens only. e.g. code-reviewer
description required string One-line summary. Shown in pour list and pour search
version optional semver e.g. 1.0.0. Used by pour update to detect changes
tags optional string[] Keywords for pour search. e.g. [coding, review, typescript]
agents optional string[] Agents this skill is optimized for. e.g. [claude, cursor, windsurf]

Body

Everything after the closing --- is the skill content — the instructions, prompt, or rules that get installed into the AI agent. Write it as if you are directly instructing the AI.

---
name: sql-expert
description: Writes optimized SQL queries for PostgreSQL
version: 1.0.0
tags: [sql, database, postgres]
agents: [claude, cursor]
---

# SQL Expert

You are an expert PostgreSQL engineer.

When asked to write SQL:
- Always use CTEs for complex queries
- Add indexes where appropriate
- Explain query plans when relevant
- Prefer explicit column names over SELECT *

Naming Rules

  • name must be lowercase
  • Use hyphens, not underscores: code-reviewer not code_reviewer
  • Must be unique within the same repo
  • Folder name should match the name field in frontmatter

Publishing Your Skill

No registration or submission needed. Push your repo to GitHub — it's instantly installable:

# create a skill
pour init my-skill

# push to GitHub, then anyone can install it
pour add your-username/your-repo -a claude
Tip: Skills are compatible across agents since the body is plain Markdown. Use the agents field to document which agents you've tested with, but users can install to any agent.
Ready to create your first skill?
$ pour init my-skill
